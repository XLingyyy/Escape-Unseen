# 模型交接

交付文件按模型名配套：`SM_*.fbx`、`SM_*_baseColor.png`、`SM_*.blend`。`_work` 保留原始 Tripo FBX 压缩包、完整提示词、生成请求、处理脚本、尺寸报告和预览；不要把整个 `_work` 导入 UE。

全部交付版采用单个静态网格、单材质和单张 baseColor PNG，无骨骼、动画、灯光或背景。三角面上限 15,000。Blender 源场景单位为厘米（`scale_length=0.01`），网格正面 +X、上方 +Z，原点位于包围盒底部中心。

FBX 导出使用 Y Forward / Z Up，以保持已整理好的网格坐标；该导出参数与角色实际朝向是不同概念。参照 [Epic BlenderTools 的导出/导入配置](https://github.com/EpicGamesExt/BlenderTools/blob/main/tests/test_files/send2ue_templates/template_1.json)，导入时以静态网格、缩放 1、旋转 0 为起点，不额外强制 Front XAxis 或重复换算厘米。PNG 使用 sRGB，接 Base Color；粗糙度可从 0.75 起调。

已对看守 FBX 做一次重新导入检查：高 150 cm、底部 Z=0、原点 0、单材质、14,500 三角面、无骨骼和动画。其余模型复用相同导出流程，并分别检查处理报告与渲染预览。灯罩另外检查了底面开口。尚未进入 UE，碰撞、最终材质和场景尺寸由 Claude 集成时处理。

Tripo 首轮 H3.1 共 385 积分；四件超时重试 H3.0 共 160 积分；囚犯和床最后用 H2.5 重试共 80 积分。累计请求消耗 625 积分（任务预算 3000）。原始超时任务仍保留，完整记录见 `_work/tripo_jobs.json`。最终来源以 `PROVENANCE.csv` 中各交付文件的记录为准；同一来源的 FBX、PNG、Blend 属于一次生成费用，不要重复相加。
